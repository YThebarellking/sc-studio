# SC Studio

Репозиторий дистрибутива **SC Studio 2.4-feature-update.3**. Здесь хранится готовый JAR-файл и публикуются бинарные сборки через GitHub Releases.

> В репозиторий добавлен предоставленный JAR. Исходный код проекта и система воспроизводимой сборки в загруженном файле отсутствуют, поэтому релиз загружает готовый артефакт, а не компилирует приложение.

## Скачать

Откройте вкладку **Releases** и скачайте `sc-studio_test.jar` из последнего релиза. Если релиз ещё не создан, JAR доступен в корне репозитория.

## Запуск

Требуется **Java 17 или новее**.

1. Установите Java, если она ещё не установлена.
2. Откройте терминал в каталоге с файлом.
3. Выполните:

```powershell
java -jar .\sc-studio_test.jar
```

Проверить установленную Java можно командой `java -version`.

## Публикация нового релиза

Workflow `.github/workflows/release.yml` автоматически создаёт GitHub Release и прикрепляет JAR, когда в репозиторий отправляется новый тег, начинающийся с `v`.

Для первой публикации из локальной папки репозитория:

```bash
git init
git add .
git commit -m "Prepare SC Studio release repository"
git branch -M main
git remote add origin https://github.com/USERNAME/sc-studio.git
git push -u origin main
git tag v2.4-feature-update.3
git push origin v2.4-feature-update.3
```

Замените `USERNAME` на имя своего GitHub-аккаунта. Сначала создайте пустой репозиторий `sc-studio` на GitHub. В настройках репозитория в **Settings → Actions → General → Workflow permissions** проверьте, что workflow разрешено записывать содержимое репозитория, если настройки организации этого требуют. В workflow уже запрошено право `contents: write`.

Для следующего релиза обновите `VERSION` и `RELEASE_NOTES.md`, при необходимости замените JAR, создайте новый тег (`v...`) и отправьте его. Теги должны быть уникальными.
